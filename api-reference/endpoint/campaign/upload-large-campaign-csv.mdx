The calling window, retries and caller numbers are not sent here; they go with [Start large campaign calls](/api-reference/endpoint/campaign/make-large-campaign-calls-async).

The flow: upload → poll [upload status](/api-reference/endpoint/campaign/get-large-campaign-upload-status) until it is `draft` → [start calls](/api-reference/endpoint/campaign/make-large-campaign-calls-async).

## Fields

The CSV follows the same rules as for [Upload campaign contact list](/api-reference/endpoint/campaign/upload-campaign-contact-list#the-csv). A list may have up to 100 rows by default, and up to 5,000 once Company details are saved in the dashboard; a longer list returns `402`. Contact Ringg for a higher limit.

- Invalid rows never fail this upload: the valid rows load and the invalid ones are left out. With `remove_invalid_rows` off, the uploader is also emailed the invalid rows.
- `transliterate_fields` is a JSON array of the agent's own variable names, not CSV headers, whose values are transliterated into the agent's language. Each must be mapped in `variables_map`, and `mobile_number` is not allowed. `transliterate_callee_name=true` is the same as adding `callee_name`.

```bash
curl --request POST "https://prod-api.ringg.ai/ca/api/v0/campaign/upload-csv" \
  --header "X-API-KEY: $RINGG_API_KEY" \
  --form 'agent_id="your-agent-id"' \
  --form 'campaign_name="EMI reminders - October"' \
  --form 'country_code="+91"' \
  --form 'variables_map="{\"mobile_number\":\"mobile_number\",\"callee_name\":\"callee_name\"}"' \
  --form 'remove_invalid_rows="true"' \
  --form "file=@emi-reminders.csv"
```

## Response

```json
{
  "message": "CSV uploaded successfully. Processing in background.",
  "bulk_list_id": "123e4567-e89b-12d3-a456-426614174000",
  "status": "verifying",
  "total_rows": 5000,
  "campaign_name": "EMI reminders - October"
}
```

`total_rows` counts the rows in the file, not counting fully blank rows. Valid and invalid counts come from [upload status](/api-reference/endpoint/campaign/get-large-campaign-upload-status) once validation finishes.

Store `bulk_list_id`. It is the campaign's ID in every later call, in call history and in analytics.

A campaign's `id` is the `list_id` or `bulk_list_id` returned when its list was uploaded, so you can match rows to the campaigns you created.

## Statuses

| `campaign_status` | Meaning |
|---|---|
| `verifying` | The uploaded list is being validated |
| `draft` | Validated, calls not started |
| `insufficient_balance` | The workspace balance does not cover the list. Listing the campaigns re-checks it and moves it back to `draft` once the balance covers it |
| `preparing` | Launched; calls are being prepared |
| `scheduled` | Calls are waiting for the start time |
| `ongoing` | Calls are being placed |
| `completed` | The campaign has finished |
| `terminated` | Stopped with [Terminate calls](/api-reference/endpoint/terminate/campaign) |
| `no_valid_contacts` | Every row in the list was invalid |
| `failed` | The list or the launch failed |
| `processing` | A workflow campaign is being prepared |
| `null` | The row is a list that is not a campaign, such as a contact list |

## Notes

- `limit` defaults to `10`; page with `offset`.
- `total_calls` is the number of valid contacts loaded from the list, not the number of calls placed. It is `0` until the list has been validated. `invalidated_rows_count` is the number of rows dropped as invalid.
- Rows in `insufficient_balance` also carry `additional_balance_required`, the extra balance needed, as a decimal string.
- For the calls inside one campaign, use [call history](/api-reference/endpoint/history/get-call-history) with `bulk_list_id`.

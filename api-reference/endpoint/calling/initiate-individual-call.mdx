Use it for calls triggered by an event in your product, such as a missed EMI or a new lead, and to [test an agent](/documentation/build-agents/test-and-improve/test-an-agent) before a campaign. To have Ringg choose the caller number from a [number pool](/documentation/inventory/phone-numbers/number-pools) (rotation and spam skipping), use the [number-pool variant](/api-reference/endpoint/calling/initiate-individual-call-v2).

`agent_id` comes from [List agents](/api-reference/endpoint/assistant/get-assistants) and `from_number_id` from [List workspace numbers](/api-reference/endpoint/numbers/get-workspace-numbers). Send `from_number_id` or `from_number`, not both. When the agent version has its own outbound numbers, those are used instead, and both fields may be left out. `name` is used as `callee_name` when `custom_args_values` does not set one.

```json
{
  "name": "John Doe",
  "mobile_number": "+919876543210",
  "agent_id": "your-agent-id",
  "from_number_id": "your-from-number-id",
  "custom_args_values": {
    "callee_name": "John",
    "order_id": "ORD-1042"
  }
}
```

The response's `data.call_id` identifies the call in [call details](/api-reference/endpoint/history/get-call-details), [call history](/api-reference/endpoint/history/get-call-history) and [webhook payloads](/documentation/build-agents/customize-agent-behaviour/webhooks/call-events). Store it with your own record.

## Call settings for this call

`call_config` overrides the agent's settings for this call only:

- `max_call_length` (seconds), `idle_timeout_warning` and `idle_timeout_end` (seconds of silence);
- `call_time`: `call_start_time`, `call_end_time` (`HH:MM`) and `timezone`, the window the call may be placed in, and `scheduled_at` to place the call later;
- `call_retry_config`: `retry_count`, and the wait in minutes before retrying a busy (`retry_busy`), unanswered (`retry_not_picked`) or failed (`retry_failed`) call.

```json
{
  "call_config": {
    "call_time": { "call_start_time": "09:00", "call_end_time": "18:00", "timezone": "Asia/Kolkata" },
    "call_retry_config": { "retry_count": 1, "retry_busy": 30, "retry_not_picked": 30, "retry_failed": 30 }
  }
}
```

## Schedule the call

`call_config.call_time.scheduled_at` places the call later. Write it as a local time without an offset, `YYYY-MM-DDTHH:MM:SS`, in `call_time.timezone` (the agent's timezone when that is not sent). It must be in the future; a time outside the calling window moves to the next opening.

```json
{
  "call_config": {
    "call_time": { "scheduled_at": "2026-10-18T15:30:00", "timezone": "Asia/Kolkata" }
  }
}
```

The response says "Call has been scheduled successfully for …" and returns `data.scheduled_at`, `data.scheduled_timezone` and `data.scheduled_time_utc`.

## Call limits and deadlines

The workspace and agent [call limits](/documentation/manage-account/call-limits) apply to calls placed by API. The request is still accepted with `200`; the limit is checked just before dialling.

- `call_validity_hours` and `call_deadline` give the call a deadline. A call held by a limit waits until then (`call_status` `registered`, `call_sub_status` `FREQUENCY_DEFERRED`), and is cancelled with `DEADLINE_PASSED` if it has not been placed by the deadline. `call_validity_hours` counts from when the call is created, or from `scheduled_at`; when both are sent, the earlier deadline applies.
- A call with no deadline is cancelled as soon as a limit blocks it (`cancelled`, `FREQUENCY_CAPPED`).
- `purpose: "transactional"` marks a transactional call; the call limits do not apply to it.

```json
{
  "call_validity_hours": 6,
  "purpose": "transactional"
}
```

## Name formatting

`smart_formatter` cleans `callee_name` before the call. `extract_first_name` drops titles and keeps the first name (`Mr Rajesh Kumar` becomes `Rajesh`). `transliteration` also converts the name to `transliteration_language.target` (default `hi`) and turns on first-name extraction. The original name stays available as `original_callee_name` in `custom_args_values`.

```json
{
  "smart_formatter": {
    "extract_first_name": true,
    "transliteration": true,
    "transliteration_language": { "source": "en", "target": "hi" }
  }
}
```

## Troubleshooting

| Symptom | Check |
|---|---|
| `401` | `X-API-KEY` is missing or the key was regenerated. |
| `400` | No caller number and no outbound numbers on the agent version, a Ringg test number as the caller number, or a missing variable in `custom_args_values`. |
| `402` | The balance, or the available credit limit, does not cover the call. |
| `422` | A required field is missing or has the wrong type, or both `from_number_id` and `from_number` are set. |
| The call stays `registered` | The current time is outside `call_time`, or a call limit is holding it (`call_sub_status` `FREQUENCY_DEFERRED`). |
| The agent says the wrong name or value | A `custom_args_values` key does not match the variable name in the prompt. |

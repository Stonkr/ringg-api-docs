Webhooks are the better fit for reacting to each call as it ends ([Event Subscription](/documentation/build-agents/customize-agent-behaviour/event-subscription)); use this endpoint for dashboards, backfills and checking that no webhook was missed.

## Notes

- `start_date` and `end_date` take a timezone offset, for example `2026-10-01T00:00:00+05:30`. `bulk_list_id` is the campaign's ID. `status` is one of `registered`, `ongoing`, `retry`, `error`, `completed`, `failed`, `cancelled`, `forwarded`. Repeat `agent_id`, `status` or `bulk_list_id` to filter by several values.
- `limit` defaults to `10`; more than `200` returns `400`. Page with `offset`.
- The list allows 10 requests per workspace per minute; more return `429`.
- `transcript` is a JSON-encoded string; parse it to get the turns.
- The response's `total` is the number of calls matching the filters, for paging.
- `audio_recording` links may expire. Fetch a fresh link from [Get call details](/api-reference/monitoring/call-history/get-call-details), and download recordings you need to keep.
- For one call with its post-call analysis, use [Get call details](/api-reference/monitoring/call-history/get-call-details). To get many calls as a CSV by email, use [Download call history](/api-reference/monitoring/call-history/download-call-history), or add `download=true` here with the same filters.

## Export by email

`download=true` emails a CSV of every matching call instead of returning a page (`limit` and `offset` are ignored). Add `email` to send it to specific teammates instead of the requester; repeat it for several people:

```bash
curl --request GET \
  --url 'https://prod-api.ringg.ai/ca/api/v0/calling/history?download=true&start_date=2025-09-25T00:00:00%2B05:30&end_date=2025-09-25T23:59:59%2B05:30&email=ops@example.com&email=qa@example.com' \
  --header 'X-API-KEY: <x-api-key>'
```

<Warning>
**Each recipient must be a member of your workspace.** The export is only emailed to people who belong to the workspace: they were invited, accepted the invite, and haven't been removed. An address outside the workspace gets a `400` and no one receives the export. To send it to someone new, invite them to the workspace first.
</Warning>

The response is `{"message": "Call history export has been queued. You will receive an email shortly.", "emails": ["ops@example.com", "qa@example.com"]}`. Without `email`, the link goes to the requester (with an API key, the workspace owner). The rules are the same as [Download call history](/api-reference/monitoring/call-history/download-call-history#choose-who-receives-the-export).

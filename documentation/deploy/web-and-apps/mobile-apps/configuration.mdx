`RinggWidgetConfig` controls how the widget looks and starts in your app; the agent's prompt, voice and tools stay in the dashboard. Only `agentId` is required. Every other field falls back to a default generated from one source for all platforms, so the web, React Native and Flutter widgets behave identically when a field is left unset; theme values with no default listed fall back to the packaged Ringg palette. Pick your framework with the switcher next to the table of contents, and [install the package](/documentation/deploy/web-and-apps/mobile-apps/install) first.

<View title="React Native" icon="smartphone">
  `RinggWidgetConfig` is the object you pass to `<RinggWidget config />` from `@ringg/react-native`.

  ```tsx
  <RinggWidget
    config={{
      agentId: "your-agent-id",
      authorization: "Bearer your-webcall-public-key",
      clientOrigin: appOrigin(BUNDLE_ID),
      title: "Support",
      defaultTab: "text",
    }}
  />
  ```

  ## Identity and auth

  <Danger>
  `authorization` and `clientOrigin` ship inside your app and can be extracted from it. Use the agent's webcall public key. The config type also accepts `xApiKey`; never put your workspace [API key](/documentation/manage-account/api-key) there, because it isn't limited to one agent or to your **Allowed clients**.
  </Danger>

  <ResponseField name="agentId" type="string" required>
    The agent to load.
  </ResponseField>

  <ResponseField name="authorization" type="string">
    `Bearer <webcall-public-key>`, from the agent's embed snippet.
  </ResponseField>

  <ResponseField name="clientOrigin" type="string">
    Caller identity sent as `Origin`, built with `appOrigin(BUNDLE_ID)`. Required for real calls; see [Caller identity](/documentation/deploy/web-and-apps/mobile-apps/install#caller-identity).
  </ResponseField>

  <ResponseField name="mode" type="string" default="prod">
    Leave it unset.
  </ResponseField>

  ## Variables

  `variables` fill the agent's [variables](/documentation/build-agents/customize-agent-behaviour/custom-variables). Values are sent as given, so strings, numbers, booleans, objects and arrays all work. Set them at controller creation; to change them for a new conversation, create a new controller.

  ```tsx
  variables: {
    callee_name: "John",
    account_id: "ACC-42",
    is_premium: true,
    cart: { items: 3, total: 149.5 },
  }
  ```

  `variables` fill the agent's [variables](/documentation/build-agents/customize-agent-behaviour/custom-variables). `WidgetVariables` is `Map<String, Object>`, and values are sent as given, so any JSON value works.   RinggWidgetConfig(
  ```dart
    agentId: 'your-agent-id',

      'is_premium': true,
      'cart': {'items': 3, 'total': 149.5},

  )
  ```

  ## Caller identity

  <OriginRequirement />

  On Flutter this is handled for you. The package reads the running app's id through `package_info_plus` and sends `<platform>://<bundleId>`:

  | Platform | `Origin` sent |
  |---|---|
  | Android | `android://<applicationId>` |
  | iOS | `ios://<bundleId>` |
  | macOS, Windows, Linux | `macos://…`, `windows://…`, `linux://…` |

  Set `clientOrigin` only when you want to pin one value, for example a single canonical string across build flavors. It wins over the derived one.

  ```dart
  RinggWidgetConfig(
    agentId: 'your-agent-id',
    clientOrigin: 'android://com.yourcompany.yourapp',
  )
  ```

  Supplying your own `ControllerPorts(httpClient: …)` opts out of the default header. Wrap your client to keep it:

  ```dart
  ControllerPorts(
    transport: transport.transport,
    httpClient: appOriginHttpClient(inner: yourClient),
  )
  ```

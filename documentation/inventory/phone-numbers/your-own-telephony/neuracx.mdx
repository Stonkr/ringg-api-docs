## Overview

NeuraCX connects to Ringg over **voice streaming**: once a call is answered, NeuraCX opens a WebSocket to Ringg that carries the call's audio both ways, and a call events webhook reports each call's outcome. NeuraCX handles the phone network; Ringg runs the AI agent on the stream.

| Direction | How the call starts |
| - | - |
| **Outbound** | Ringg asks NeuraCX's outbound calling API to dial the customer from your NeuraCX number. When the customer answers, NeuraCX opens your account's **Stream URL**. |
| **Inbound** | A customer calls your NeuraCX number. NeuraCX opens the Stream URL set on that number. |

You register two URLs in NeuraCX, both specific to your Ringg NeuraCX account:

| URL | Registered as |
| - | - |
| **Stream URL (WebSocket)** | The WebSocket in NeuraCX **Developer → Webhooks**, and each inbound number's stream URL |
| **Call events URL** | The HTTP Webhook in NeuraCX **Developer → Webhooks** |

<Note>
  Ringg records every NeuraCX call itself, so recordings, transcripts and call analysis appear in Ringg as for any other provider.
</Note>

## Prerequisites

* A NeuraCX account with API access, its **API key** and **Client ID** (NeuraCX **Developer → API Keys**)
* At least one NeuraCX number
* A Ringg workspace with the **Numbers** permission, and an assistant ready to take calls

## Step 1: Add NeuraCX as a telephony provider in Ringg

<Steps>
  <Step title="Open the NeuraCX account form">
    Go to **Numbers → Add number** and select **NeuraCX**. With no NeuraCX account yet, the form opens on its own; otherwise open **Configure provider** (the gear) and select **Add**.
  </Step>
  <Step title="Enter credentials">
    All fields are required. Leading and trailing spaces are removed when you save.

    | Field | Value |
    | - | - |
    | **Name** | Your label, for example `NeuraCX Mumbai` |
    | **API Key** | Your NeuraCX API key (**Developer → API Keys**) |
    | **Client ID** | Your NeuraCX Client ID, shown at the top of **Developer → API Keys** |
  </Step>
  <Step title="Save">
    NeuraCX has no credential-test endpoint, so the account is saved without a live check. The first test call (Step 4) confirms the credentials work.
  </Step>
  <Step title="Add your numbers">
    Select **Add custom** and enter each NeuraCX number with its country code, for example `+919876543210`. NeuraCX numbers are added manually: there is no **Buy new** or **Import** option for NeuraCX.
  </Step>
  <Step title="Assign the numbers">
    Attach each inbound number to the assistant that should answer it, and choose NeuraCX numbers as the caller ID for outbound calls and campaigns.
  </Step>
</Steps>

## Step 2: Register the URLs in NeuraCX

<Steps>
  <Step title="Reveal the URLs">
    In **Numbers → Add number**, select **NeuraCX**. Each NeuraCX account has a **Call setup** card. Select **Reveal** to show its **Stream URL (WebSocket)** and **Call events URL**, and copy each one.
  </Step>
  <Step title="Register them in NeuraCX">
    In the NeuraCX portal, go to **Developer → Webhooks**. Register the **Stream URL** as the **WebSocket** and the **Call events URL** as the **HTTP Webhook**. Copy each URL in full, including everything after `?`.
  </Step>
</Steps>

<Warning>
  Treat these URLs like passwords: each carries a token that ties calls to your Ringg account. They are hidden until you select **Reveal**, and **Hide** removes them from the page.
</Warning>

The URLs never change for your account, so you register them once. Two cases add more URLs to the card:

* **More than one group** (for example **Default** and **India cluster (agents set to India)**): your assistants can run in more than one Ringg cluster. Register every pair shown, or calls from assistants in the missing cluster will not connect.
* **Pending key rotation — also register:** Ringg is replacing the key that signs your URLs. Register these URLs alongside your current ones; your current URLs keep working until the rotation completes.

Leave NeuraCX's optional payload encryption off. Ringg does not support encrypted payloads.

## Step 3: Point inbound numbers at Ringg

For each NeuraCX number that should answer inbound calls, set its stream URL in the NeuraCX portal to your account's **Stream URL**, and its call events webhook to the **Call events URL**.

Each pair of URLs belongs to one Ringg NeuraCX account. A call to a number that is on a different Ringg account is rejected, so if you use several NeuraCX accounts in Ringg, give each number its own account's URLs.

## Step 4: Place a test call

* **Outbound**: place a call from the assistant to your own phone, from **Test call** or the outbound call API. Your phone rings from the NeuraCX number; when you answer, the assistant speaks.
* **Inbound**: call your NeuraCX number from any phone. The attached assistant answers.

## Call status

NeuraCX reports calls that never reach the assistant to the Call events URL. Calls the assistant handled are reported by the assistant itself.

| NeuraCX event | Reported in Ringg as |
| - | - |
| `call.failed`, reason containing "busy" | Busy |
| `call.failed`, reason containing "no answer", "not responding" or "timeout" | No answer |
| `call.failed`, any other reason (rejected, cancelled, declined, …) | Failed, with NeuraCX's reason |
| `call.expired` | Failed (`expired`) |
| `call.completed`, but the assistant never started | Failed |

Each call is reported once, even if NeuraCX sends the same event again.

## Call features

| Feature | Supported |
| - | - |
| Outbound and inbound calls | Yes |
| Recording, transcript, analysis | Yes, recorded by Ringg |
| Call transfer | Yes, with the **Call Transfer** tool. The target must be in E.164 format, for example `+919876543210`. After the transfer, NeuraCX carries the call. |
| Sending keypad tones (DTMF) from the assistant | No |
| Hangup | Either side can end the call; Ringg tells NeuraCX to hang up when the assistant ends it |
| Maximum call length | The assistant's maximum call length, up to 2 hours (NeuraCX's limit) |

## URL reference

| Purpose | Registered in NeuraCX as | URL |
| - | - | - |
| Stream URL | WebSocket (Developer → Webhooks), and each inbound number's stream URL | `wss://<ringg-host>/pc/v1/neuracx/ws?region=in&token=ncx1_…`, copied from the **Call setup** card |
| Call events URL | HTTP Webhook (Developer → Webhooks) | `https://<ringg-host>/pc/v1/neuracx/events?region=in&token=ncx1_…`, copied from the **Call setup** card |

Always copy the URLs from the card rather than building them by hand: the token is specific to your account.

## Troubleshooting

| Symptom | Likely cause |
| - | - |
| Outbound call fails with `NeuraCX dial refused: …` | NeuraCX rejected the dial: a wrong API key or Client ID, or a caller ID that is not on your NeuraCX account. The message carries NeuraCX's reason. |
| Outbound call fails with `NeuraCX credentials not configured` | The API key or Client ID is missing on the NeuraCX account in Ringg. |
| The customer answers but the assistant never speaks | The Stream URL is not registered in NeuraCX, was copied without its `?region=…&token=…` part, or belongs to another cluster than the assistant's (register every pair on the card); or payload encryption is on. |
| Busy or unanswered calls stay in progress | The Call events URL is not registered as the HTTP Webhook. |
| Inbound calls are not answered | The number's stream URL is not your account's Stream URL, the number is on a different Ringg NeuraCX account, or the number has no assistant attached in Ringg. Numbers must be in international format, for example `+919876543210`. |
| **Reveal** shows "You need the Numbers permission to view these URLs." | Ask a workspace owner for the **Numbers** permission. |
| **Reveal** shows "NeuraCX isn't configured on Ringg yet — contact support." | NeuraCX is not enabled on Ringg's side yet. Contact the Ringg team. |
| **Reveal** shows "Too many requests. Try again in a minute." | The URLs can be revealed 10 times a minute. Wait a minute and select **Retry**. |
